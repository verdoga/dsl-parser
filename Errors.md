| Код | Ошибка | Точное условие и описание препятствия | Основание |
| --- | --- | --- | --- |
| P001 | Некорректная кодировка UTF-8 | Во входных байтах обнаружена недопустимая последовательность UTF-8. Нельзя получить исходные символы документа без их замены или потери. Замена повреждённых байтов на символ замены не является успешным разбором исходника. | 1.13 |
| P002 | Неподдерживаемый перевод строки | Обнаружен CR, не входящий в CRLF. Спецификация не определяет его как допустимый перевод строки; парсер не должен самовольно превращать его в LF или пробел. | 1.13 |
| P003 | Неизвестная DSL-конструкция | В контексте распознавания DSL-тегов строка начинается с неэкранированного `@`, но имя не соответствует поддерживаемому тегу. Например, `@unknown` или `@noteText`. Нет правила построения узла для этого имени; превращать строку в обычный текст нельзя. | 1.15–1.16, 1.29 |
| P004 | Нарушен обязательный разделитель объявления | Между распознаваемым тегом, отдельными служебными параметрами или открывающей скобкой отсутствует требуемый пробел U+0020 либо вместо него стоит только табуляция. Например, `@note{` или табуляция между `@media` и `audio`. Объявление не соответствует форме токенов. Внутренние пробелы и табуляции свободного текста под эту ошибку не подпадают. | 1.2, 1.29 |
| P005 | Использована неподдерживаемая форма тега | Объявление пытается использовать блочную форму однострочного тега либо однострочную форму исключительно блочного тега. Например, `@question {`, `@task task-1 {`, `@variant A {` или `@table Data` без открывающей скобки. Выбранная форма не имеет продукции в грамматике данного тега. | Форматы тегов в разделах 2–4; таблица форм ниже |
| P006 | Отсутствует обязательный структурный параметр | Не передан отдельный обязательный операнд: `ID` у `@task`, `@document-id`, `@fragment`, `@include`; `NUMBER` у `@order`; `TYPE` или `SOURCE` у `@media`. Например, `@fragment {` или `@media audio`. Нельзя завершить разбор объявленной формы с предусмотренными операндами. Проверка допустимости уже выделенного значения — отдельная задача. Объявление версии рассматривается отдельно в V001–V002. | 1.32.1–1.32.2, 1.34.1, 2.3.2–2.3.3, 3.1.2–3.1.4, 3.12.3–3.12.4, 3.13.3–3.13.4 |
| P007 | Лишние параметры или запрещённое содержимое объявления | После завершённой формы остаются токены, для которых в ней нет места. Примеры: `@endtask task-1`, `@include part extra`, `@fragment part extra {`, `@hint Title {`, `@variants Title {`. Парсер не может присоединить эти токены к предусмотренному полю. В свободном `TITLE`, `NAME`, `INSTRUCTION` или текстовом содержимом дополнительные слова не являются лишними параметрами. | 1.29, 2.4.3, 2.6.3, 3.11.8, 3.12.7, 3.13.7, 4.1.6, 4.9.5 |
| P008 | Неправильное открытие блока | Открывающая скобка вынесена на отдельную строку либо после структурной `{` в строке объявления есть содержимое. Например, отдельная `{` или `@text { Hello`. Граница блока записана не по построчной грамматике. Скобки ответа плейсхолдера сюда не относятся. | 1.18 |
| P009 | Закрытие несуществующего блока | После удаления крайних пробелов и табуляций строка состоит из неэкранированной `}`, но стек открытых фигурных блоков пуст. Закрывающей конструкции не соответствует открывающая. | 1.19 |
| P010 | Неправильная строка закрытия блока | Структурная закрывающая скобка совмещена с текстом или другой конструкцией: например, `} @note Text` или `} }`. Допустимое закрытие — отдельная строка `}`. Парсер не должен разрезать такую строку на несколько DSL-конструкций. Скобка внутри ответа плейсхолдера обрабатывается по P028–P029. | 1.16, 1.19 |
| P011 | Незакрытый блок | Достигнут конец файла, а стек фигурных блоков непуст. В AST не определена корректная граница хотя бы одного блока. В сообщении указываются тег и место открывающей скобки. | 1.20 |
| P012 | Неэкранированная фигурная скобка в текстовом значении | Неэкранированная `{` или `}` встретилась там, где она не образует разрешённую границу блока или конструкцию ответа плейсхолдера. Например, `Use {x} here.` как обычный учебный текст. Для литеральных скобок предусмотрены `\{` и `\}`; парсер не выбирает за автора между литералом и разметкой. Специальные правила буквальных путей `@resource-dir` имеют приоритет. | 1.17–1.22, 1.35.8, 4.3.7–4.3.10 |
| P013 | Не удалось получить объявление версии | После удаления допустимого начального BOM первая строка не является корректной формой `@dsl-version VERSION`: тег отсутствует, находится ниже, отсутствует значение, нарушен разделитель или есть лишние параметры. При режиме выбора грамматики по документу нельзя надёжно выбрать её без предположения. | 1.1–1.4, 1.13, 1.29 |
| P014 | Версия не поддерживается | Значение версии выделено, но для него нет реализации грамматики. Для парсера только DSL v1.2 это любое значение, отличное от `1.2`. Сообщение должно содержать полученную и поддерживаемые версии. Это не утверждение о синтаксической испорченности документа другой версии. | 1.2 |

# Формы тегов для P005–P007

| Группа | Теги и формы |
| --- | --- |
| Только строка, без параметров | `@endtask`, `@speaking`, `@newpage`. |
| Только строка, с отдельными параметрами | `@dsl-version VERSION`, `@document-id ID`, `@order NUMBER`, `@task ID`, `@include ID`, `@media TYPE SOURCE`. |
| Только строка, со свободным значением | `@section NAME`, `@header TITLE`, `@step TITLE`, `@question TEXT`, `@variant NAME`. Слова внутри значения не становятся дополнительными параметрами. |
| Только строка, список путей | `@resource-dir PATH[, PATH …]`, со специальными правилами кавычек и запятых. |
| Строка с текстом либо блок без параметров | `@editor`, `@instr`, `@hint`, `@answer`. В блочной форме между тегом и `{` не должно быть названия. |
| Строка с текстом либо блок с необязательным названием | `@example`, `@wordlist`, `@note`, `@alt`. |
| Только блок с необязательным названием | `@table`, `@script`, `@text`, `@key`. |
| Только блок с необязательной инструкцией | `@choice`, `@multichoice`, `@matching`, `@ordering`. |
| Только блок с обязательным ID | `@fragment ID { … }`. |
| Только блок без параметров | `@variants { … }`. |
| Все четыре формы | `@multifill`; `@multifill INSTRUCTION`; `@multifill { … }`; `@multifill INSTRUCTION { … }`. |

# Контексты и исключения

| Контекст | Правило структурного разбора |
| --- | --- |
| Содержимое `@example`, `@wordlist`, `@table`, `@script`, `@text`, `@key`, `@note`, `@alt`, `@hint`, `@answer` | Вложенные DSL-теги запрещены. Заголовки не становятся вложенными структурными заголовками. Встроенная HTML-разметка разрешена только в содержимом `@text`. |
| Блочный `@instr` | Вложение `@hint` разрешено; другие DSL-теги запрещены. Проверка количества `@hint` может выполняться по готовому AST. |
| `@fragment` | Разрешены обычный текст и `@media`, `@example`, `@wordlist`, `@table`, `@script`, `@text`, `@instr`, `@note`, `@alt`, `@hint`. Внутри каждого дочернего блока действуют его собственные ограничения. |
| `@choice`, `@multichoice` | Обычные строки — варианты; `@answer` создаёт правильные варианты; `@hint` допустим как непосредственно следующая за ответом подсказка. Других вложенных DSL-тегов нет. |
| `@matching`, `@ordering` | До разделителя разрешены элементы, связанные `@answer` и следующие за ними `@hint`. После разделителя находятся только текстовые варианты/позиции. В сокращённом `@ordering` разделителя нет. |
| `@variants` | До первой ветви — только пустые строки и `@editor`. Внутри ветвей действуют разрешения 4.9.21–4.9.24. Заголовки `#`–`###`, `@newpage` и вложенный `@variants` запрещены. `@variant` не открывает собственный фигурный блок. |
| Блочный `@editor` | Строки, похожие на DSL-теги и заголовки, являются содержимым комментария. Не следует выдавать для них P003, P013 или P014. Неэкранированная отдельная `}` завершает блок; общие правила скобок и экранирования сохраняются. |
| Предзаполненное содержимое `@multifill` | Похожие на теги и заголовки строки — текст. Исключение: неэкранированное имя `@answer` в начале строки явно запрещено. Распознаются плейсхолдеры и граница блока. Строка `@hint Text` здесь сама по себе не создаёт вложенной подсказки. |
| `@media` | Внутри заключённого в кавычки `SOURCE` последовательность `\"` обозначает литеральную кавычку, `\\` — литеральную обратную косую черту. Значение `"12"` — путь, а не номер. |
| `@resource-dir` | Обратная косая черта буквальна и не экранирует кавычку. Запятая внутри кавычек входит в путь, вне кавычек разделяет элементы списка. Не использовать для этого тега обработчик экранирования `@media` без специального режима. |
