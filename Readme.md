# dslparser

Консольный парсер DSL 1.2. Находит TXT-файлы, разбирает содержимое и сохраняет
результат в JSON рядом с каждым источником: `example.txt` → `example.json`.
Печатает результат каждого файла и итоговую статистику. Версия приложения —
`1.0.4`, объявлена константой `version` в `main.go`.

## Сборка

Требуется Go 1.25.1 или новее. В корне проекта выполните:

```sh
go build -o dslparser .
```

Для Windows: `go build -o dslparser.exe .`.
Запускайте полученный файл явно: `.\dslparser.exe --help` в PowerShell
или `./dslparser --help` в Linux. Первая строка должна быть `dsl-parser v1.0.4`.

## Запуск

```sh
./dslparser --help
./dslparser example.txt
./dslparser --depth 1 ./documents
./dslparser --replace ./documents
```

- Укажите один путь к TXT-файлу или каталогу; пустой аргумент `""` означает
  текущий каталог. Флаги указываются перед путём.
- По умолчанию поиск рекурсивный, расширение `.txt` проверяется без учёта регистра.
  Символические ссылки при обходе пропускаются; явно заданный путь со ссылками
  отклоняется.
- `--depth N` ограничивает число уровней подкаталогов: `0` — только исходный
  каталог. Для отдельного файла ограничение игнорируется.
- `--replace` разрешает замену существующего JSON. Без него такой файл
  обрабатывается с отказом в сохранении.

Документ начинается со строки `@dsl-version 1.2` и должен быть в UTF-8.
Фатальные диагностики запрещают запись JSON; нефатальные сохраняются вместе
с результатом. Отказ одного файла не останавливает обработку остальных.

Коды завершения: `0` — успешные сохранения, пустая выборка или справка;
`1` — отказ обработки или сохранения, ошибка поиска либо конфигурации;
`2` — ошибка аргументов, исходного пути до поиска или вывода справки.
Нефатальные ошибки DSL при успешном сохранении сами по себе не повышают код `0`.

## Итоговая статистика

- `всего` — число обработанных TXT, включая файлы с отказом.
- `сохранено` — число фактически созданных или заменённых JSON.
- `сбоев` — число файлов с фатальной диагностикой, отказом чтения/обработки,
  сохранения или очистки. Несколько причин в одном файле дают один сбой.
- `файлов с ошибками разбора` — число фактически созданных или заменённых JSON
  с нефатальными диагностиками уровня `error` текущего запуска; техническая
  IO001 сюда не входит.
- `ошибок разбора` — сумма этих сохранённых нефатальных диагностик. Это же число
  выводится для каждого файла. Фатальная диагностика указывается отдельно.

Например, 121 сохранённый файл без диагностик и три отказа P013 дают:

```text
ИТОГО | всего: 124 | сохранено: 121 | сбоев: 3 | файлов с ошибками разбора: 0 | ошибок разбора: 0
```

Если новый JSON не записан, учитывается сбой, а оба счётчика ошибок разбора
для этого результата равны нулю. Старый JSON при отказе замены не участвует
в статистике текущего запуска. Уже установленный JSON
с последующей ошибкой очистки увеличивает и `сохранено`, и `сбоев`, поэтому
сумма этих двух полей не обязана равняться `всего`.
При ошибке поиска к итогу добавляется `обход: неполный`, код завершения — `1`.
Недоступные каталоги не превращаются в выдуманное число необработанных файлов.

Фатальные встроенные диагностики: P001, P002, P013, P014 и IO001.
P003 («Неизвестная DSL-конструкция») нефатальна: она сохраняется в JSON
вместе с результатом разбора.

`processing.durationMs` измеряется отдельно для каждого файла до сохранения
JSON, с округлением вниз до целых миллисекунд и минимумом 1 мс в этом приложении.

## Проверки

```sh
go test ./...
go vet ./...
```

`TestCLISyntheticBatches` собирает и запускает настоящий исполняемый файл
на одиннадцати синтетических наборах и двух производственных fixtures, проверяет
пофайловые строки, итоги, коды завершения, JSON и сохранность источников.
`TestCLIFileSystemFailures` добавляет три сценария отказа чтения, записи и обхода.
На системе, где отказ доступа нельзя воспроизвести, эти проверки явно пропускаются.
Для дополнительного сравнения с версией до PR17
соберите коммит `e26b285` отдельно и передайте абсолютный путь к его программе
через переменную `DSL_PARSER_BASELINE` при запуске тестов `TestCLI*`. Сравниваются
действия с файлами, коды завершения и все поля JSON, кроме пути временного
источника, версии инструмента, времени начала и длительности.
